# 에이전트 검증 반복 감소

2026-09-05에 happyGallery의 기존 작업 기록과 현재 검증 명령을 대조했다. 기록에서 확인한 사례만 반영했으며, 필수 CI 실행 시간 전체를 낭비로 계산하지 않았다.

## 확인한 사례

| 작업·근거 | 반복 비용 | 반영한 개선 |
|---|---|---|
| `추상적 문구 찾아 개선안 정리`의 문구 수정에서 환불 E2E 준비 요청이 `403 LOGIN_REQUIRED`로 실패 | 변경한 안내 문구보다 넓은 결제 복구 흐름과 환경을 확인함 | 문구는 타입·사용처부터 확인하고, 선택자가 바뀐 해당 시나리오만 실행 |
| 같은 작업에서 REST Docs 클래스를 `:adapter-in-web:test`로 실행한 뒤 `restDocsTest`로 다시 실행 | 첫 명령이 해당 tag를 제외해 목적한 검사를 수행하지 못함 | 모듈·tag별 명령을 ADR-0027과 백엔드 스킬에 명시 |
| `불필요한 검증과 구현 제거`의 main 병합 요청에서 진행 안내 30개, 첫 PR 백엔드 12분 21초·다음 PR 12분 46초 | 필수 검사를 기다리며 같은 실행 중 상태를 반복 설명함 | PR별 필수 검사는 유지하고, 실행 ID와 대기 도구·조회 간격 확대로 상태 추적 |
| 스킬 정리 중 Python 환경 두 곳에 PyYAML이 없어 별도 설치 | 문서 검사에 앱과 무관한 의존성 준비가 필요했음 | 저장소의 Ruby 기본 YAML 파서로 실행하는 스킬 검사 명령 추가 |
| 스킬 파일명 변경 후 macOS에서 Git index에 `skill.md`와 `SKILL.md`가 함께 남음 | 파일 조회는 정상이지만 Git 기록을 다시 고쳐야 했음 | 검사 명령에서 실제 파일명과 Git index를 함께 확인 |
| `api-contract` 지침이 `api:generate` 직후 `api:check`를 요구 | `frontend/package.json`의 `api:check`가 이미 재생성을 포함 | 로컬 생성·검토와 CI 생성 일치 검사를 구분 |

작업 기록 식별자: 문구 정리 `01a07093-7ec2-7af3-8b5f-4d591d36dbe9`, 검증·구현 정리 `01a0391a-d980-7192-a25a-4d550ebc3572`. 앱에서 본문이 반환되지 않은 다른 작업은 판단 근거에서 제외했다.

## 유지할 기준

- 검사를 시작할 때 대상과 종료 조건을 정하고, 통과 후에는 관련 입력이 달라진 검사만 다시 실행한다.
- 성공·실패와 함께 미확인 범위를 남겨 다음 세션이 검사를 처음부터 다시 고르지 않게 한다.
- 작업 기록·로그는 필요한 필드와 실패 구간만 가져온다. 큰 응답을 이미 받았다면 저장한 결과에서 추려 읽는다.
- 원인 구분과 재실행 조건은 [ADR-0027](../../ADR/0027_테스트_전략과_최소_테스트_세트_기준선/adr.md), 실제 작업 지시는 [AGENTS.md](../../../AGENTS.md)를 따른다.

이번 변경은 로컬 검증 선택과 결과 재사용을 개선했다. 실행 시간 절감률은 아직 측정하지 않았다.
