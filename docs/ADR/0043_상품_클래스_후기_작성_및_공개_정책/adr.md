# ADR-0043: 상품·클래스 후기 작성 및 공개 정책

**날짜**: 2026-08-08
**상태**: Accepted (`ADR-0044`가 삭제·감사·상호작용 정책을 개정함)

## 배경

후기는 구매·수강 경험을 보여 주는 공개 콘텐츠지만 Product Q&A와 달리 실제 거래 완료, 중복 작성,
별점 집계와 운영자 숨김 정책이 필요하다. 상품과 클래스의 원천 테이블이 다른 상태에서
`target_type + target_id`만 저장하면 DB 외래 키로 작성 근거를 보장할 수 없다.

## 결정

### 1. 완료 거래를 후기 작성 근거로 사용한다

- 상품은 현재 회원 소유의 주문 품목을 근거로 하며 주문이 `DELIVERED`, `PICKED_UP`, `COMPLETED`일 때만 작성한다.
- 클래스는 현재 회원 소유 예약을 근거로 하며 예약이 `COMPLETED`일 때만 작성한다.
- 비회원은 후기를 작성하지 않는다. 회원가입 뒤 이력 가져오기로 회원 소유가 된 완료 거래는 같은 규칙을 적용한다.

### 2. 단일 테이블에서도 실제 외래 키를 유지한다

- `reviews`는 상품 원천의 `order_item_id + product_id` 또는 클래스 원천의 `booking_id + class_id` 중 정확히 한 쌍을 가진다.
- 각 원천 ID의 UNIQUE 제약으로 동시 요청에서도 활성 후기 한 건만 허용한다. 삭제·재작성 시 원천 점유 세부 규칙은 `ADR-0044`를 따른다.
- 원천 ID와 대상 ID는 복합 FK로 묶어, 주문 품목과 다른 상품 또는 예약과 다른 클래스에 후기가 잘못 귀속되는 조합을 DB에서도 거절한다.
- 작성자 삭제는 `ADR-0044`에 따라 내용을 비식별화한 tombstone으로 처리한다. 숨김 이력이 없을 때만 같은 원천의 재작성을 허용한다.

### 3. 공개 상태와 집계를 같은 기준으로 맞춘다

- 상태는 `PUBLISHED`, `HIDDEN` 두 값이다.
- 공개 목록, 평균 별점과 후기 수는 모두 `PUBLISHED`만 사용한다.
- 관리자는 계정 기반 Bearer 세션으로만 숨김·재공개하고 숨김 사유, 관리자 ID와 시각을 남긴다.
- 작성자는 숨김 후기도 자기 목록에서 확인하고 수정·삭제할 수 있다. 수정만으로 자동 재공개하지 않는다.

### 4. 기존 플랫폼 경계를 재사용한다

- 입력 모양은 Bean Validation, 저장 불변식은 도메인 엔티티, 소유권과 거래 상태는 application 서비스가 검증한다.
- 목록은 기존 `(createdAt,id)` 커서와 Spring Data projection을 사용한다.
- 공개 작성자 이름은 기존 `MaskingUtil`을 사용한다.
- Controller와 DTO를 기준으로 OpenAPI와 TypeScript client를 생성하며 생성 파일을 직접 편집하지 않는다.

## 결과

### 장점

- 구매·수강 확인과 중복 방지를 애플리케이션 사전 검사와 DB 제약으로 함께 보장한다.
- 다형 대상의 편의성 때문에 실제 거래·상품·클래스 외래 키를 포기하지 않는다.
- 숨김과 공개 집계의 기준이 하나라 운영 화면과 고객 화면이 어긋나지 않는다.

### 단점과 후속 범위

- 단일 테이블에 nullable FK가 네 개 있어 정확히 한 원천 쌍이라는 CHECK가 필요하다.
- 사진 첨부와 사용자 신고는 최초 결정에서 제외했으나 `ADR-0044`에서 저장·보존·남용 방지 정책을 확정했다.
