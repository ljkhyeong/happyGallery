# ADR-0048: 스마트스토어 주문 운영 연동 경계

**날짜**: 2026-08-29
**상태**: 승인됨

## 맥락

재고 동기화만으로는 스마트스토어 주문의 발주·발송·클레임, 상품 문의, 실제 정산을 해피갤러리 관리자 화면에서 처리할 수 없다. 반대로 채널 주문을 자사 주문 상태 머신에 합치면 외부 상태와 로컬 상태가 서로 다른 시점에 확정되어 잘못된 자동 전이와 중복 처리가 생긴다. 주문 상세에는 수령인·연락처·배송지 개인정보도 포함된다.

## 결정

### 1. 채널 주문 원장을 운영 조회 모델로 확장한다

- `smartstore_product_orders`에 발주 상태·발송 기한·배송수단·택배사·운송장, 단가·결제액·수수료·정산 예정액을 저장한다.
- 수령인·연락처·주소·배송 메모는 구조화 JSON을 AES-GCM으로 암호화해 `delivery_info_enc` TEXT 한 열에 저장한다.
- 배송정보는 관리자 단건 조회에서만 복호화하며 데이터 키 회전 대상에 포함한다. 목록에는 반환하지 않는다.

### 2. 외부 명령과 로컬 상태 확정을 분리한다

- 관리자는 발주 확인, 발송·지연, 취소·반품 승인/거부, 반품 보류·보류 해제·판매자 반품 요청, 판매자 취소 요청과 교환 수거 완료·거절·보류·보류 해제·재배송을 요청할 수 있다.
- 외부 HTTP 호출 구간에는 DB 트랜잭션을 열지 않는다.
- 네이버 성공 응답 뒤 로컬 상태를 추측해 갱신하지 않는다. 다음 변경 주문 피드가 확정 상태를 원장에 반영한다.
- 인증 토큰을 준비하지 못해 주문 API를 호출하지 않은 경우는 `NOT_SENT`, 네이버의 명시적 거절은 `REJECTED`, 요청 전송 뒤 응답을 확정할 수 없는 경우는 `RESULT_UNKNOWN`으로 기록한다. 분류되지 않은 런타임 실패는 중복 실행 위험을 피하기 위해 `RESULT_UNKNOWN`으로 보수적으로 기록한다.
- 관리자 API는 `NOT_SENT`를 재시도 가능한 `503 SMARTSTORE_OPERATION_NOT_SENT`, `REJECTED`를 상태·입력 확인이 필요한 `409 SMARTSTORE_OPERATION_REJECTED`, `RESULT_UNKNOWN`을 자동 재시도하면 안 되는 `409 SMARTSTORE_OPERATION_RESULT_UNKNOWN`으로 구분해 반환한다.
- `RESULT_UNKNOWN`과 5분 넘게 완료되지 않은 `REQUESTED` 이력은 같은 DB 쿼리로 관리자 작업 목록·Prometheus 메트릭·경보에 노출한다. 자동 재전송은 하지 않으며 관리자가 네이버 현재 상태 또는 판매자센터를 확인한다.
- 수동 확인은 원래 처리 상태를 덮어쓰지 않고 `APPLIED | NOT_APPLIED`, 확인 근거, 관리자 ID·이름과 시각을 별도 필드에 남긴다. 이미 대사했거나 아직 5분이 지나지 않은 요청은 행 잠금 안에서 거절한다.
- 대사 화면의 네이버 현재 상태 조회는 감사 이력만 남고 로컬 주문 원장이 삭제됐거나 아직 수집되지 않은 경우에도 상품 주문 번호로 실행하는 읽기 전용 호출이다. 로컬 주문 원장을 조회하거나 갱신하지 않으며 확정 원장 상태와 변경 시각은 계속 변경 주문 피드만 갱신한다.
- 관리자가 `NOT_APPLIED`로 확인하면 대사 정보만 저장한 뒤 해당 상품 주문의 운영 화면을 명시적으로 열어 재처리 여부를 판단할 수 있다. 화면 이동만으로 외부 요청을 다시 보내지는 않는다.
- 교환 재배송은 네이버 운영 필수값인 배송수단·택배사 코드·운송장을 별도 요청 계약으로 받으며 일반 발송일시는 요구하지 않는다.
- 작업 가능 상태는 네이버가 최종 판정한다. 로컬 원장 상태로 같은 규칙을 다시 검증하지 않아 배치 지연 때문에 유효한 작업을 막지 않는다.
- 관리자 단건 화면의 현재 클레임 상세는 네이버에서 실시간 조회하며 사유·요청 수량·수거·배송비·보류 정보를 로컬에 중복 저장하지 않는다.
- 발주 확인과 발송은 네이버 공식 제한에 맞춰 한 번에 최대 30건을 요청한다. 응답은 성공 주문 번호와 주문별 실패 코드·메시지를 모두 보존하며 일부 실패 때문에 성공 결과를 버리지 않는다.
- 택배사 코드는 자주 쓰는 값을 화면에서 선택할 수 있게 하되 직접 입력도 허용해 네이버 코드 추가를 로컬 배포가 막지 않게 한다.
- `GET /v2/product-delivery-info/return-delivery-companies`는 스마트스토어센터의 반품 택배사 계약번호·이름·우선순위를 반환한다. 주문의 `collectDeliveryCompany`나 `deliveryCompanyCode`와 다른 식별자이므로 이름으로 코드를 추측하거나 계약번호를 자동 대입하지 않는다. 관리자 주문 화면에서 필요할 때 조회하는 참고 목록으로 제공하고 로컬 DB에는 저장하지 않는다.
- 클레임 첨부 이미지는 네이버가 반환한 주소를 관리자 단건 화면에만 표시하고 별도 저장하지 않는다.

### 3. 문의는 실시간 조회·답변으로 제공한다

- 상품 문의와 주문·배송 고객 문의를 각각 공식 페이지 응답에서 읽고 기간·미답변 필터·페이지 이동을 관리자에게 제공한다. 화면 초기 기간은 오늘을 포함한 최근 30일이며 유형별 조회 조건을 유지한다.
- 기존 배열 API는 유지하고 `/page`, `/customers/page`를 추가한다. 공통 `OffsetPage`를 사용하며 로컬 페이지는 0부터, 네이버 페이지는 1부터 시작한다. 페이지 크기는 두 외부 API가 모두 허용하는 10~100건으로 제한하고 기본은 50건이다. 미답변 조건도 네이버에 전달해 합계와 페이지 내용이 일치하게 한다.
- 새 API는 요청한 한 페이지만 읽는다. 기존 배열 API도 최대 200건을 채우는 데 필요한 상품 문의 두 페이지 또는 고객 문의 한 페이지만 읽는다. 전체 페이지를 읽은 뒤 자르는 방식은 사용하지 않는다.
- 조회 기간은 필수이며 시작일이 종료일보다 늦은 경우만 거절한다. 공식 상품·고객 문의 명세에 최대 조회 일수가 지정되어 있지 않으므로 자체 30일 제한을 추가하지 않는다. 상품 문의의 날짜는 한국 시간 하루 전체로 바꾸고 고객 문의는 날짜 그대로 전달한다.
- 상품 문의 답변은 `commentContent`, 고객 문의 답변은 `answerComment` 계약으로 직접 전송한다. 고객 식별자는 네이버가 제공한 마스킹 값만 표시한다.
- 고객 문의 조회의 nullable `answerContentId`를 전달하고, 기존 답변 수정은 문의번호와 답변번호를 지정한 PUT으로 전송한다. 편집 시작 시의 답변번호를 유지해 목록 재조회가 수정 대상을 바꾸지 않게 한다. 수정 가능 여부는 네이버가 판정하며 로컬에 문의 상태를 중복 저장하지 않는다.
- 상품 문의 화면은 네이버의 단일 답변 템플릿을 실시간 조회해 본문 적용 버튼으로 제공한다. 템플릿을 로컬에 중복 저장하지 않는다.
- 네이버 커머스 API가 후기를 제공하지 않으므로 후기 연동은 구현하지 않는다.

### 4. 정산은 별도 원장으로 대사한다

- `smartstore_settlement_sync_state`에 다음 지급일과 처리 시작 시각을 저장한다. 매시 50분 다음 지급일부터 오늘까지 한 실행당 최대 31일을 순차 처리하고, 따라잡은 뒤에는 당일을 다시 조회한다.
- 처리 성공 뒤에만 커서를 전진시키고 10분 넘게 끝나지 않은 선점은 다음 실행이 회수해 장기 장애 기간을 자동 복구한다.
- 관리자는 31일 이내 기간을 지정해 같은 멱등 대사를 수동으로 다시 실행할 수 있다.
- 상품 주문 원거래의 `settleExpectAmount`를 주문 상세의 `expectedSettlementAmount`와 비교한다.
- `MATCHED`, `ORDER_NOT_FOUND`, `EXPECTED_AMOUNT_MISSING`, `AMOUNT_MISMATCH`, `NOT_APPLICABLE`로 저장한다.
- 정산 불일치는 주문·재고·결제 상태를 자동 변경하지 않고 관리자 오늘 할 일과 주문 화면에만 표시한다.

### 5. 회계 자료 조회는 대사 원장과 분리한다

- 31일 이내 기간의 일별 정산, 지급일 기준 수수료 상세, 일별 부가세 자료를 네이버에서 조회한다.
- 부가세 API는 전월 말까지만 제공하므로 조회 기간을 전월 말로 자르고 `vatAvailableThrough`로 실제 제공 종료일을 반환한다.
- 구매자명·예금주·계좌번호는 회계 화면 목적에 필요하지 않으므로 애플리케이션 응답에 포함하지 않는다.
- 회계 자료는 로컬 주문 상태를 판정하거나 변경하지 않는 읽기 전용 응답이며, CSV 생성은 관리자 브라우저에서 수행한다.

## 결과

- 관리자는 해피갤러리 운영 화면에서 스마트스토어 주문 처리·문의 답변·정산 확인을 이어서 수행할 수 있다.
- 외부 상태의 최종 확정은 변경 피드에 남아 일시적인 성공 응답이나 화면 재시도로 로컬 상태가 앞서가지 않는다.
- 처리 결과를 알 수 없는 외부 요청은 자동 재시도하지 않고 운영 작업으로 남으며, 장애 당시 결과와 관리자의 사후 확인 근거를 함께 추적할 수 있다.
- 배송 개인정보가 목록과 평문 DB에 남지 않고 기존 키 회전 절차로 관리된다.
- 정산 API가 7일보다 오래 중단돼도 지급일 커서가 남아 누락 날짜를 순서대로 다시 처리한다.
- 운영 대사와 회계 증빙 조회가 서로의 상태와 커서를 오염시키지 않는다.
