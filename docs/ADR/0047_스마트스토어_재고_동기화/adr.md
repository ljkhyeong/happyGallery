# ADR-0047: 스마트스토어 재고 동기화

**날짜**: 2026-08-29
**상태**: 승인됨

---

## 맥락

해피갤러리는 온라인 주문뿐 아니라 오프라인 판매와 관리자 조정으로도 재고가 바뀐다. 같은 상품을 스마트스토어에서도
판매하려면 기성품 수량과 주문제작 옵션 조합별 수량을 빠르게 맞춰야 한다. 재고 트랜잭션 안에서 네이버 API를 직접
호출하면 외부 지연 동안 DB 잠금을 오래 잡고, 트랜잭션 롤백 뒤 외부 재고만 바뀌는 문제가 생긴다.

## 결정

### 1. 해피갤러리 재고를 원본으로 단방향 반영한다

- 관리자는 상품별 스마트스토어 `originProductNo`를 저장한다.
- 기성품은 상품 단위 재고를 네이버 멀티 상품 변경 API의 `STOCK` 절대값으로 보낸다.
- 주문제작 상품은 모든 `ProductVariant`에 네이버 옵션 `id`를 매핑하고, 한 원상품의 전체 옵션 재고를 옵션 재고 변경 API 한 번에 보낸다.
- 직접입력형 옵션은 SKU 재고를 나누지 않으므로 별도 네이버 재고 매핑을 만들지 않는다.
- 스마트스토어 주문을 해피갤러리로 가져오는 양방향 재고 예약은 이번 범위에 포함하지 않는다.

### 2. 재고 변경 트랜잭션에는 동기화 요청만 저장한다

- 주문 차감, 환불·거절 복구, 교환 차감과 관리자 수동 조정은 재고 저장 뒤 같은 트랜잭션에서 상품별 요청 버전을 올린다.
- 상품에 활성 매핑이 없으면 동기화 행을 만들지 않는다.
- 짧은 시간에 여러 번 바뀐 재고는 한 상품의 요청 버전으로 합치고, 외부 전송 시점의 최신 절대 수량을 읽는다.
- 외부 호출은 DB 트랜잭션 밖에서 수행한다.

### 3. 오래된 완료 결과가 최신 재고를 덮지 않게 한다

- 배치는 대기 행을 잠그고 현재 요청 버전을 선점한 뒤 재고와 매핑 스냅샷을 만든다.
- 외부 호출 중 새 재고 변경이 요청 버전을 올리면 이전 호출 성공 뒤에도 행을 `SYNCED`로 끝내지 않고 다시 `PENDING`으로 둔다.
- 절대 수량 변경은 같은 값을 다시 보내도 누적되지 않으므로 5분 넘은 `PROCESSING` 행을 재선점할 수 있다.
- 실패는 최대 30분 간격의 지수 백오프로 10회 재시도하고, 이후 `FAILED`로 남겨 관리자가 원인을 보고 재시도한다.

### 4. 네이버 인증 정보는 런타임 설정으로만 관리한다

- OAuth2 Client Credentials 토큰은 `client_id + timestamp`를 네이버가 발급한 bcrypt salt 형식의 client secret으로 해시하고 Base64 URL 인코딩해 발급한다.
- 토큰은 메모리에 보관하고 만료 60초 전에 갱신하며, `401`이면 한 번 강제 재발급 후 같은 절대 재고 요청을 다시 보낸다.
- client secret과 access token은 DB와 로그에 저장하지 않는다.

## 결과

- 재고 잠금과 외부 네트워크 지연이 분리된다.
- 여러 재고 변경이 마지막 절대 수량으로 합쳐져 네이버 호출 수와 순서 역전 위험이 줄어든다.
- 관리자는 상품 화면에서 연동 상태와 마지막 오류를 확인하고 재시도하거나 연동을 해제할 수 있다.
- 양방향 판매를 운영하려면 스마트스토어 주문 수집과 주문 멱등성, 채널 간 재고 예약 정책을 별도 결정해야 한다.
