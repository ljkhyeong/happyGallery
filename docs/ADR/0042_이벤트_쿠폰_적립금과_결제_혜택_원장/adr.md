# ADR-0042: 이벤트·쿠폰·적립금과 결제 혜택 원장

## 상태

채택

## 배경

회원 상품 주문에 쿠폰과 적립금을 추가하면 결제 prepare와 confirm 사이, 결제 시도 만료, 전액 취소와 부분 클레임에서 같은 혜택을 중복 사용하거나 잘못 복원할 수 있다. 단일 `totalAmount`만으로는 PG 환불액과 적립금 복원액, 품목별 부분 환불 상한도 재현할 수 없다.

이벤트는 게시 기간과 홈 추천, 관련 상품을 가지므로 조회수·고정 공지 중심의 공지사항과 수명주기와 관리 목적이 다르다.

## 결정

### 이벤트

- 이벤트를 공지와 분리한 aggregate와 테이블로 관리한다.
- 게시 여부, 시작·종료 시각, 홈 추천 여부, 이미지와 관련 상품을 영속화한다.
- 공개 조회는 `[시작 시각, 종료 시각)` 경계를 사용해 종료 시각에 도달하지 않은 게시 이벤트만 반환하고, 관리자 변경은 낙관적 락 버전을 요구한다.
- 열린 상세 화면은 다음 시작·종료 경계 직후 다시 조회한다. 종료 뒤 404는 공개 수명주기의 정상 종결로 처리해 이전 상세를 숨기고 해당 화면의 반복 조회를 멈춘다.

### 쿠폰

- 관리자 정책인 `coupon_definitions`와 회원 권리인 `issued_coupons`를 분리한다.
- 발급 쿠폰은 `AVAILABLE → RESERVED → REDEEMED` 상태를 기본으로 하며 만료·취소 상태를 별도로 둔다.
- 회원 상품 주문 한 건에 쿠폰 한 장만 사용하고 배송비는 할인 기준에서 제외한다.
- prepare에서 발급 쿠폰 행을 배타 잠그고 쿠폰 정의 행을 공유 잠금 조회한 견적을 만들어 결제 시도 저장과 같은 트랜잭션에서 예약한다. 정의 공유 잠금은 관리자 비활성화와 prepare를 직렬화하고 MySQL 반복 읽기의 과거 스냅샷이 있어도 최신 커밋 상태로 사용 가능성을 판정하면서, 서로 다른 회원의 같은 정의 결제 견적은 병렬로 허용한다. confirm 주문 생성과 같은 트랜잭션에서 사용 확정하고 안전한 결제 종결에서만 예약을 해제한다.
- 한 장이라도 발급된 쿠폰 정의는 이름·할인 방식·금액·최소 주문 금액·유효 기간을 변경하지 않는다. 운영 중 변경은 활성·공개 여부로 제한해 이미 발급된 회원 권리의 의미를 보존한다.
- 공개 발급은 쿠폰 정의에 공유 비관적 읽기 잠금을 사용해 관리자 수정과는 직렬화하되, 서로 다른 회원의 같은 쿠폰 발급은 병렬로 처리한다. 회원별 중복은 DB 유일 제약으로 최종 보장한다.
- 발급 가능 목록은 전체 정의와 전체 회원 발급 이력을 메모리에서 조합하지 않고, 유효한 공개 정의와 회원 미발급 조건을 `NOT EXISTS` 쿼리로 계산해 최신 100개로 제한한다.
- 정률 할인은 원 미만을 버린다. 계산 결과가 0원이면 쿠폰 ID가 있는 0원 할인 스냅샷을 만들지 않고 쿠폰 정책 경계에서 적용 불가로 거절한다.
- 쿠폰 정의를 비활성화하면 아직 사용하지 않은 발급 쿠폰은 회원 조회 시 취소 상태로 수렴시킨다. 결제에 사용한 뒤 만료된 쿠폰은 전액 취소 시 사용 참조를 감사 이력으로 유지한 채 만료 상태로 복원한다.

### 적립금

- `reward_accounts`는 사용 가능·예약·부채 합계를, `reward_lots`는 만료 시각이 있는 적립 단위를 보존한다.
- 결제 시도별 예약과 적립 단위별 배분을 별도 테이블에 남기고, 모든 증감은 멱등키가 있는 `reward_ledger`에 기록한다.
- 만료가 가까운 적립 단위부터 사용한다. 배송·픽업 완료 시 혜택 적용 뒤 상품 순결제액의 1%를 원 단위로 내려 적립하고 1년 뒤 만료한다.
- 환불 회수 시 사용 가능 적립금이 부족하면 음수 사용 가능 잔액 대신 부채를 남기고 이후 적립·복원·예약 해제 반환액으로 먼저 상환한다. 예약 해제는 원래 만료가 가까운 배분부터 부채에 상계하고 실제 사용 가능해진 금액만 같은 적립 단위에 되돌려 장기 유효 잔액을 보존한다.
- 사용 적립금 환불은 예약 배분이 가리키는 원 적립 lot의 주문 출처를 새 복원 lot에도 유지한다. 그래야 같은 환불에서 이어지는 주문 적립 회수가 복원 lot를 해당 주문의 신규 적립으로 오인하지 않고 원래 만료 정책도 보존된다.
- 예약 해제 도중 일부 적립 단위가 만료되면 `RELEASE`는 반환된 금액과 만료액이 남은 예약 잔액을, 뒤따르는 `EXPIRE`는 만료액 제거 뒤 잔액을 기록한다. 두 사건이 같은 최종 스냅샷을 중복 기록하지 않도록 원장만으로도 증감을 재현한다.
- 복원·회수 멱등 키는 각각 예약 행과 회원 행을 직렬화한 뒤 다시 확인한다. 같은 키의 동시 요청은 한 번만 반영하면서 모든 호출을 성공으로 수렴시킨다.

### 주문·환불 금액

- 주문에는 상품액, 배송비, 쿠폰 할인, 적립금 사용, PG 결제액과 적립 기준액을 저장한다.
- 주문 품목에는 원금, 쿠폰 배분, 적립금 배분과 순결제액을 저장한다. 합계 보존이 필요한 원 단위 배분은 `BigInteger`를 사용하는 최대 나머지 방식으로 overflow 없이 계산한다.
- 환불은 고객 반환 총액, PG 취소액, 적립금 복원·회수액과 쿠폰 복원 여부를 분리한다. PG 취소액이 0원이면 외부 결제사를 호출하지 않고 같은 환불 성공 후처리 경계를 사용한다.
- `restoreCoupon`은 쿠폰 후처리 대상임을 뜻하며 환불 완료 시점의 유효기간에 따라 최종 상태는 `AVAILABLE` 또는 `EXPIRED`다. 상태를 함께 반환하지 않는 고객 화면에서는 재사용 가능 복원을 단정하지 않고 "쿠폰 사용 상태 정리"로 표시한다.

### PG 불확실성과 혜택 예약

- PG 호출 전에 확정적으로 끝난 실패는 결제 시도를 `FAILED`로 종결하고 쿠폰·적립금 예약을 즉시 해제한다.
- `PROCESSING` 진입 뒤의 실패나 재시도 중 비재시도 오류처럼 PG 승인 가능성을 배제할 수 없는 경우는 `RECONCILIATION_REQUIRED`로 보내고 혜택 예약을 유지한다.
- PG 조회에서 미승인이 확인된 때만 예약을 해제한다. 늦은 승인 발견 시에는 보존한 예약을 사용 확정해 같은 쿠폰·적립금이 다른 주문에 먼저 쓰이는 경쟁을 막는다.

### 화면 예상 금액과 서버 확정 금액

- 프론트는 입력 즉시 반응하는 예상 쿠폰·적립금 금액만 작은 순수 함수로 계산하고 예상값임을 표시한다. 최종 금액과 사용 가능 여부의 권위는 항상 서버 결제 prepare가 가진다.
- 현재 `quoteAndLock`은 쿠폰·회원·적립금 행 잠금과 만료 반영을 포함하는 결제 정합성 경계이므로 화면 입력마다 호출하는 조회 API로 재사용하지 않는다.
- 결제 전 서버 확정 견적이 별도 요구가 되면 잠금·예약·`PaymentAttempt` 생성이 없는 순수 가격 계산기를 `OrderPreparer`와 공유하는 API를 별도로 설계한다.

## 표준 라이브러리와 프레임워크 사용 판단

- 트랜잭션 전파, 행 잠금과 낙관적 락은 Spring Transaction과 JPA의 표준 기능을 사용한다. 별도 트랜잭션·락 프레임워크를 만들지 않는다.
- 시간 정책은 주입된 `Clock`, 금액 overflow는 `Math.*Exact`, 비례 배분 중간 계산은 JDK `BigInteger`를 사용한다.
- Java·Spring·현재 사용 라이브러리는 쿠폰 유효성, 적립금 만료 단위, 환불 복구 같은 사업 상태기계를 제공하지 않는다. 이 부분만 도메인 모델로 유지하고 저장소·트랜잭션·검증은 기존 추상화를 재사용한다.

## 결과

- prepare 뒤 가격이나 혜택 정책이 바뀌어도 confirm은 저장된 견적을 검증해 같은 주문을 만든다.
- 결제 시도 만료와 재시도, 0원 PG 주문, 부분 환불을 동일한 멱등 경계에서 처리할 수 있다.
- 테이블과 상태가 늘어나므로 마이그레이션 제약, 테스트 데이터 정리 순서와 원장 멱등키를 회귀 테스트로 유지해야 한다.
