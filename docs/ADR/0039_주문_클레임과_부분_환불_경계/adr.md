# ADR-0039: 주문 클레임과 부분 환불 경계

**날짜**: 2026-07-24
**상태**: Accepted

## 컨텍스트

주문 완료 뒤 하자·오배송·단순 변심을 주문 전체 환불로만 처리하면 일부 품목·수량의 환불과 교환 이력을 표현할 수 없다. 기존 `refunds.order_id` 유일 제약도 주문별 부분 환불을 허용하지 않았다.

## 결정

### 1. 클레임은 주문 항목과 수량을 별도 집계한다

- `DELIVERED`, `PICKED_UP`, `COMPLETED` 주문만 접수한다.
- 회원은 세션, 비회원은 기존 주문 접근 토큰으로 소유권을 확인한다.
- `order_claims`에 유형·요청 해결 방법·사유·처리 상태와 관리자를, `order_claim_items`에 주문 항목과 수량을 저장한다.
- 같은 주문 행을 잠근 상태에서 거절되지 않은 기존 접수 수량을 합산해 주문 수량 초과를 막는다.
- 클레임 항목은 `(claim_id, order_id)`와 `(order_item_id, order_id)` 복합 외래키로 같은 주문에
  속함을 보장한다.

### 2. 주문 직접 환불과 클레임 환불을 구분한다

- 주문 취소·거절 같은 전체 직접 환불은 주문당 한 건을 유지한다.
- 클레임 환불은 클레임당 한 건을 허용하고 `refunds.order_claim_id`로 연결한다.
- 클레임 환불의 `(order_claim_id, order_id)`도 복합 외래키로 묶어 원결제 주문과
  완료할 클레임 주문이 달라질 수 없게 한다.
- 승인 환불액 중 상품 대금은 클레임 항목의 결제 금액 비율로 원 단위 배분해
  `order_claim_items.approved_refund_amount`에 고정한다. 나눗셈 잔여 원은 큰 나머지 순,
  주문 항목 ID 순으로 배분하고 배송비 환불액은 상품별 매출에 배분하지 않는다.
- 클레임 환불도 기존 요청 선커밋, 커밋 뒤 PG 실행, processing token fencing, 재시도·대사 경계를 그대로 사용한다.
- PG 성공 트랜잭션에서 연결된 클레임을 `COMPLETED`로 종결한다.

### 3. 재고 처리는 실제 물류 의미를 따른다

- 관리자가 반품품을 다시 판매할 수 있다고 판단한 경우에만 접수 수량을 복구한다.
- 환불 승인은 선택한 복구만 적용한다.
- 교환 승인은 반품 복구 여부와 무관하게 같은 품목·수량의 교환품 재고를 차감한다. 반품품을 복구하면 순변화는 0, 복구하지 않으면 교환품 수량만 감소한다.

## 결과

- 고객은 품목별 남은 접수 가능 수량과 처리·환불 상태를 조회한다.
- 관리자는 접수·환불 진행·교환 승인·완료 상태를 운영 화면에서 처리한다.
- 인기 상품 통계는 직접 주문 환불과 클레임 항목 배분액을 분리 차감하므로 한 품목의
  부분 환불이 같은 주문의 다른 품목 매출을 되돌리지 않는다.
- 활성 클레임이 있는 회원은 처리 완료 전 탈퇴할 수 없다.
