# ADR-0019: 비밀번호 해시 정책 (Salt + Key Stretching)

**날짜**: 2026-03-06  
**최종 갱신**: 2026-07-19
**상태**: Accepted

---

## 컨텍스트

사용자 비밀번호 저장 시 단순 해시(SHA-256, MD5)를 그대로 사용하면
오프라인 크래킹 및 사전(Rainbow Table) 공격에 취약하다.

본 프로젝트는 현재 관리자 인증/인가 체계를 확장 중이며,
사용자 계정 비밀번호 정책을 사전에 고정해 구현 편차를 방지할 필요가 있다.

---

## 결정 사항

### 1. 단순 해시 저장을 금지한다

- SHA-256, MD5 등 단순 해시 단독 사용 금지
- 커스텀 해시 포맷(직접 Salt/반복 구현)도 기본 정책에서 제외

### 2. Salt + Key Stretching 기반 알고리즘만 허용한다

- 허용 알고리즘: `BCrypt`, `Argon2id`, `Scrypt`
- 기본 구현 표준:
  - Spring Security `PasswordEncoder` 사용
  - 기본 권장 구현체는 `BCryptPasswordEncoder`

### 3. 저장/운영 원칙을 고정한다

- DB에는 평문 비밀번호를 저장하지 않는다
- 운영 로그에는 비밀번호 및 해시 원문을 남기지 않는다
- 해시 비교는 반드시 `PasswordEncoder.matches(...)`를 사용한다

### 4. 비밀번호 변경과 재설정 정책을 구분한다

- 로그인 회원의 변경은 현재 비밀번호를 확인한 뒤 새 해시를 저장한다.
- 분실 재설정은 가입 이메일, 회원에게 저장된 검증 휴대폰 번호, 미소모 SMS 인증 코드를 모두 확인한다.
- 재설정 실패는 계정·전화번호·코드 중 어떤 값이 틀렸는지 구분하지 않고 `PASSWORD_RESET_FAILED`로 응답한다.
- 소셜 로그인만 사용해 `password_hash=null`인 회원은 현재 비밀번호 변경을 사용할 수 없고, SMS 재설정으로 최초 로컬 비밀번호를 설정한다.
- 현재 비밀번호와 같은 새 비밀번호는 허용하지 않는다.
- 비밀번호 해시를 저장할 때 `credential_version`을 증가시키고 변경 전 버전으로 발급된 기존 회원 세션을 모두 무효화한다. 변경 후 버전으로 새로 발급된 세션은 보존한다. 세션 상세 기준은 ADR-0023을 따른다.

## 결과 (트레이드오프)

| 항목 | 내용 |
|------|------|
| 장점 | 크래킹 난이도 상승 및 단순 해시 기반 취약점 제거 |
| 장점 | Spring Security 표준 사용으로 구현 일관성 확보 |
| 단점 | 인증 시 CPU 비용 증가 |
| 대응 | 로그인/인증 엔드포인트에 Rate Limiting 적용, 필요 시 해시 강도(cost) 단계적 조정 |

## 구현 반영

- PRD 반영:
  - `docs/PRD/0001_기준_스펙/spec.md`
    - `9.1 사용자/게스트`의 `users.password_hash` 정책 명시
    - `12. 비기능 요구사항 > 보안`에 비밀번호 저장 정책 추가
- 관리자 최초 설정과 인증된 비밀번호 변경도 같은 `PasswordEncoder`와 BCrypt 정책을 사용한다.
- 관리자 비밀번호 변경은 현재 해시를 `matches(...)`로 다시 확인하고, 성공 시 자격 증명 버전을 증가시켜 기존 Bearer 세션을 모두 무효화한다.
