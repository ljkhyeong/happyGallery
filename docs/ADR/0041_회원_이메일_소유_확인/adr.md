# ADR-0041: 회원 기준 이메일 소유 확인

**날짜**: 2026-07-29
**상태**: Accepted

---

## 컨텍스트

Google OIDC는 `email_verified=true`인 프로필을 제공하지만 Naver 프로필 이메일은 서비스의
기준 이메일 소유권으로 신뢰하지 않는다. 이메일 문자열이 같다는 사실도 기존 happyGallery 회원의
소유권을 증명하지 않으므로 자동 계정 병합에 사용할 수 없다.

그 결과 Naver로 처음 가입한 회원은 `users.email_enc/email_hmac=null`로 시작한다. 이 회원이
이메일 로그인과 비밀번호 재설정에 사용할 기준 이메일을 직접 등록하려면 provider 프로필과 독립된
메일함 소유 확인, 동시 등록 경합 제어와 기존 세션 폐기가 필요하다.

## 결정

### 1. provider 이메일과 회원 기준 이메일의 신뢰 경계를 분리한다

- Naver provider ID와 이름만 신규 회원 생성에 사용하고 Naver 프로필 이메일은 저장·충돌 조회·자동 병합에 사용하지 않는다.
- `CustomerUserResponse.email=null`은 검증된 기준 이메일이 아직 없다는 뜻이다.
- 기준 이메일이 없는 로그인 회원은 자체 소유 확인을 거쳐 이메일을 한 번 등록할 수 있다. 현재 회원에게 이미 기준 이메일이 있으면 변경 API로 재사용하지 않고 `EMAIL_ALREADY_EXISTS`로 거절한다.
- 다른 회원의 같은 이메일도 자동 병합하지 않고 `EMAIL_ALREADY_EXISTS`로 거절한다.

### 2. 최근 본인 확인과 현재 자격 버전을 모두 요구한다

- `POST /api/v1/me/email-verifications`가 인증 코드를 발송하고 `PATCH /api/v1/me/email`이 검증한 이메일을 등록한다.
- 두 요청 모두 `HG_SESSION`, SPA CSRF와 최근 10분 안에 완료한 비밀번호 또는 이미 연결된 소셜 계정 재인증을 요구한다.
- 최근 본인 확인은 회원 ID와 `credential_version`에 결합한다. 발송과 등록 트랜잭션은 잠근 회원 행의 현재 버전을 다시 확인한다.
- 이메일은 앞뒤 공백을 제거하고 소문자로 통일하며 최대 254자로 제한한다. 인증 코드는 6자리 숫자이고 5분간 유효하다.

### 3. 발급, 외부 발송과 발송 완료를 분리한다

- 인증 행 생성은 새 트랜잭션으로 먼저 커밋한다.
- SMTP는 DB 트랜잭션 밖에서 호출해 회원 행 잠금과 DB connection을 외부 네트워크 대기 시간 동안 점유하지 않는다.
- SMTP 성공 뒤 별도 새 트랜잭션이 해당 행을 잠그고 `delivered=true`로 바꾼다. `delivered=true`인 코드만 검증할 수 있다.
- 같은 회원의 발송 성공 요청 중 더 큰 인증 ID가 이전 미소모 행을 무효화한다. 새 SMTP 발송이 실패하면 기존 정상 코드는 그대로 유지한다. 늦게 끝난 이전 요청도 최신 성공 코드를 다시 덮지 못한다.
- 발송 실패는 `503 SERVICE_UNAVAILABLE`로 응답한다. 서버가 자동 재발송하지 않으며 사용자가 새 코드를 요청한다.

### 4. 인증 원문을 DB 검색 키로 남기지 않는다

- `email_verifications`는 회원 ID, 발급 당시 자격 버전, `email_hmac`, 회원 ID·정규화 이메일·코드를 결합한 `code_hmac`, `code_enc`, 발송·검증 상태와 만료 시각을 저장한다.
- 이메일 원문과 이메일 암호문은 저장하지 않는다. `code_enc`는 보호된 행을 복원·재저장하고 local/dev의 E2E 코드 조회를 지원하되 운영 응답에는 노출하지 않는다.
- 로그에는 이메일과 인증 코드 원문을 남기지 않는다. local/dev/test 가짜 발송기도 발송 목적만 기록한다.

### 5. 등록의 최종 정합성은 회원 행 잠금과 DB 유일 제약이 보장한다

- 등록은 회원 행을 비관적 잠금으로 읽고 현재 자격 버전, 최근 본인 확인과 `email=null`을 다시 검증한다.
- 회원 ID·자격 버전·정규화 이메일·코드가 모두 맞는 발송 완료·미검증·미만료 행을 잠가 한 번 소비한다.
- 이메일 사전 조회는 빠른 실패용일 뿐이다. 동시 등록의 최종 승자는 `users.email_hmac` 유일 제약을 확인하는 `saveAndFlush`가 정하며, 충돌은 `409 EMAIL_ALREADY_EXISTS`로 번역한다.
- 성공하면 회원의 이메일 암호문/HMAC을 저장하고 `credential_version`을 증가시킨다. 자격 변경 이벤트와 현재 요청의 명시적 unbind를 통해 이전 버전의 모든 회원 세션을 폐기하고 새 이메일로 다시 로그인하게 한다.

### 6. 이메일 등록과 로컬 비밀번호 설정을 분리한다

- 이메일 등록만으로 임의의 로컬 비밀번호를 만들지 않는다.
- 기준 이메일과 검증된 휴대폰을 모두 가진 소셜 전용 회원은 기존
  `POST /api/v1/auth/password/reset`의 `PASSWORD_RESET` SMS 인증으로 최초 로컬 비밀번호를 설정한다.
- 따라서 Naver 회원도 자체 이메일 등록과 휴대폰 소유 확인을 마치면 기존 복구 경계를 그대로 사용할 수 있다.

### 7. 전용 SMTP와 수명 주기를 둔다

- 운영은 회원 이메일 소유 확인 전용 SMTP sender를 사용한다. 별도 제한 큐 executor와 CircuitBreaker,
  SMTP transport 제한 합보다 큰 전용 TimeLimiter로 보호한다.
- STARTTLS와 직접 SSL 중 정확히 하나를 필수로 하고, STARTTLS downgrade를 허용하지 않으며
  서버 인증서의 호스트명을 검증한다.
- 이 즉시 검증 흐름은 일반 업무 알림의 `notification_outbox`, Alimtalk/SMS fallback과 분리한다. 일반 영수증·보조 이메일 채널 구현 여부와도 별개다.
- local/dev/test는 코드를 로그나 응답에 노출하지 않는 가짜 sender를 사용하고, local/dev 관리자 코드 조회 API만 암호문을 복호화한다.
- 만료된 인증 행은 만료 후 1일 뒤 개인정보 보존 배치가 `(expires_at, id)` 순서로 100건씩 삭제한다.
- HMAC 키 회전 시 이메일 원문이 없어 `email_hmac`과 결합 `code_hmac`을 다시 만들 수 없으므로 인증 행을 전량 삭제한다. 사용자는 회전 뒤 새 코드를 요청한다.

## 결과

### 장점

- Naver 프로필 이메일이나 단순 이메일 일치로 다른 회원 계정을 획득하거나 자동 병합하는 경로가 없다.
- 외부 SMTP 지연과 실패가 회원 행 잠금 트랜잭션을 길게 유지하지 않는다.
- 발송 성공, 코드 소비, 동시 이메일 등록과 세션 무효화의 정합성 경계가 명확하다.
- 기존 SMS 비밀번호 재설정과 중복되는 새 비밀번호 발급 흐름을 만들지 않는다.

### 단점과 대응

- Naver 전용 회원은 이메일 등록과 휴대폰 등록을 모두 마쳐야 SMS 기반 최초 로컬 비밀번호를 설정할 수 있다. 마이페이지에서 각 미등록 상태와 다음 행동을 구분해 안내한다.
- SMTP가 성공했지만 발송 완료 저장이 실패하면 코드를 사용할 수 없다. 결과가 불명확한 코드를 자동 활성화하지 않고 사용자가 재발송하게 한다.
- 키 회전은 진행 중 이메일 인증을 무효화한다. 유지보수 창과 사용자 재요청을 전제로 한다.
