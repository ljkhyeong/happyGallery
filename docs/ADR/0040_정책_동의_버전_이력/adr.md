# ADR-0040: 정책 동의 버전 이력

**날짜**: 2026-07-24
**최종 갱신**: 2026-08-11
**상태**: Accepted

## 컨텍스트

이용약관과 개인정보처리방침 화면만 공개하면 회원가입과 비회원 거래 시 어떤 버전에 동의했는지 재현할 수 없다. 클라이언트가 보낸 동의 시각을 신뢰하거나 회원 행의 현재 값만 덮어쓰는 방식도 과거 거래 근거를 잃는다.

## 결정

- 현재 이용약관·개인정보처리방침 버전과 문서 경로를 `/api/v1/policies/current`로 제공한다.
- 문서 경로는 `/terms/{version}`, `/privacy/{version}`이며 해당 버전의 본문은 이후 공방 프로필이나 현재 정책이 바뀌어도 수정하지 않는다. 새 본문은 새 버전과 새 렌더링 분기로 추가한다.
- 프론트는 정책 종류별 `version -> immutable document component` registry를 단일 원본으로 사용한다. 기존 version entry와 본문은 수정하지 않고 새 버전만 추가하며, registry에 없는 경로는 존재하지 않는 문서로 처리한다.
- 후기 본문·사진·신고와 운영 판단 증거의 처리·보존 고지는 기존 문서를 덮어쓰지 않고 개인정보처리방침
  `2026-08-11-v1`로 발행한다. 이용약관의 현재 버전은 `2026-08-08-v1`을 유지하며 정책 종류별 현재
  버전을 독립적으로 관리한다.
- 이메일 회원가입, 처음 보는 Google·Naver 계정의 신규 회원 생성, 비회원 주문·예약 prepare는 두 정책의 현재 버전과 명시적 동의를 요구한다.
- 서버가 현재 버전을 다시 검증하고 `policy_consents`에 유형, 목적, 버전, 서버 수락 시각을 append-only 행으로 저장한다.
- 동의 주체는 회원 또는 결제 시도 중 정확히 하나다. 비회원 동의는 결제 시도와 같은 트랜잭션에 저장해 거래 귀속을 유지한다.
- OAuth 신규 가입 동의는 CSRF 보호 POST가 현재 HTTP 세션에 5분짜리 불투명 가입 의도를 만든 뒤,
  해당 시도 ID로 생성한 authorization request의 provider와 OAuth `state`에 한 번 결합한다.
  callback은 provider·state·만료가 모두 유효한 의도를 한 번 소비한다. 공개 OAuth GET query의
  동의 값은 신뢰하지 않으며 계정 연결과 기존 회원 로그인에는 가입 의도를 사용하지 않는다.
- 기존 회원 로그인과 회원 거래는 매번 재동의를 요구하지 않는다. 향후 재동의 정책이 필요하면 별도 버전 전환 규칙으로 추가한다.
- 서버의 현재 버전 설정과 프론트의 버전별 문서는 같은 배포 단위로 갱신한다. 서버가 반환하는 현재 버전에 대응하는 문서가 없는 배포는 허용하지 않는다.

## 결과

- 클라이언트 시각이나 변경 가능한 공방 프로필에 의존하지 않고 가입·비회원 거래 당시 동의 버전과 본문을 재현할 수 있다.
- 동의 이력은 개인정보·결제 시도 보존 정책과 함께 백업·삭제 기준을 관리해야 한다.
