# happyGallery 문서

## 문서 선택

- 제품 정책·HTTP 계약·설계 결정·실행 안내의 담당 문서는 `AGENTS.md`를 따른다. 원문을 먼저 수정하고 관련 요약과 링크만 갱신한다.
- `docs/Idea`는 검토 중인 제안, `docs/POC`는 실험, `docs/Retrospective`는 회고를 담는다. 채택한 설계는 ADR에 반영하되, 단순 수정마다 ADR을 만들지 않는다.
- PRD-0002는 전환 배경, PRD-0003은 제외 범위 문서다. 현재 요구사항으로 채택하려면 먼저 문서 역할을 변경한다.
- 생성 OpenAPI와 TypeScript를 고쳐 문서에 맞추지 않는다. 계약 변경은 `api-contract`로 원본을 수정하고 재생성한다.

## 정리 기준

- 현재 코드와 대조해 완료된 계획, 오래된 경로·수치, 중복 설명을 정리한다. 배포 파일의 존재만으로 실제 배포가 끝났다고 쓰지 않는다.
- 스킬은 담당 범위와 필요한 판단만 남긴다. 공통 지시, 코드로 조회할 전체 목록, 과거 작업에만 필요했던 체크리스트는 삭제한다.
- 파일을 옮기거나 삭제하면 참조하는 문서와 스킬도 고친다. `HANDOFF.md`에는 다음 작업에 필요한 상태만 남긴다.

## 검증

- 수정한 설명을 코드와 대조하고, 링크·파일 경로·용어를 확인한다. 문서만 바꾸면 앱 빌드와 테스트는 실행하지 않는다.
- 스킬 변경은 `ruby tools/check-agent-skills.rb`로 YAML·이름·참조·Git 파일명을 한 번 확인하고, 변경한 규칙의 적용 범위를 검토한다. 검사만을 위해 Python 패키지를 설치하지 않는다.
- 파일명 대소문자를 바꾸면 임시 이름을 거쳐 `git mv`하고, Git index에도 최종 이름만 남았는지 확인한다. 같은 내용을 다른 이름으로 다시 추가하지 않는다.
