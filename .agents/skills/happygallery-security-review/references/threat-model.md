# 위협 모델 절차

모든 구성·흐름·통제 주장에는 저장소 경로나 ADR 근거를 단다. 근거가 없으면 가정으로 적는다.

## 1. 범위

- 요청 경로를 운영 runtime, CI·배포 script, 테스트·local 전용 코드로 나눈다. local API key·가짜 sender·local 코드 조회 API는 운영 위협에서 빼되 운영 profile로 새는 경로는 포함한다.
- 단일 노트북 k3s·운영 미개시 상태·운영자 1인 전제를 적는다(ADR-0037). Ingress 앞에 공유기 외 프록시가 생기면 전달 헤더 경계가 바뀐다(ADR-0028 Known Gaps).

## 2. 경계·자산·진입점

- SKILL.md의 신뢰 경계를 기준으로 범위 안 진입점만 표로 만든다. 열: 경로·메서드, 인증 수단(없음·회원 세션·비회원 token·관리자 Bearer·웹훅 서명), CSRF, 처리율 규칙·실패 모드, 근거 클래스.
- 진입점 원본은 `SecurityConfig` 허용 목록, `CustomerSecurityRoutes`, `RateLimitFilter` 규칙, `deploy/k3s/base`의 Ingress·NetworkPolicy, batch scheduler다. 직접 목록을 만들지 말고 이 원본에서 추린다.

## 3. 공격자 모델

- 기본 능력: 인터넷 익명 사용자(공개 API·SSR·웹훅 경로 직접 호출, 여러 IP), 자기 세션·token만 가진 회원·비회원(다른 ID 추측), URL·공유 기기·화면에서 비회원 token이나 관리자 Bearer를 얻은 사람.
- 기본 비능력: cluster 내부 네트워크·Actuator·MySQL·Redis 직접 접근(NetworkPolicy·`validate.sh`), 서명 키 없는 비회원 token 위조(`AccessTokenSigner`), TLS 위변조 없는 외부 제공자 응답 조작.
- 운영자 단말·Secret·백업 접근은 별도 시나리오로 다룬다. 비능력은 근거가 있을 때만 적용한다.

## 4. 악용 경로

- 자산별 목표(유출·권한 상승·무결성 훼손·가용성)를 정하고 `전제 → 단계 → 영향`으로 5~10개만 쓴다. 단계마다 근거 경로를 단다.
- 우선 검토할 경로: 비회원 token 유출·재사용, 소유권 누락, 결제 금액·혜택 조작, OAuth 연결·재인증 탈취, fail-open 구간이나 수신자 버킷을 이용한 SMS·이메일 비용 남용과 특정 사용자 차단, 로그·Sentry PII 유출, 이미지 디코딩 자원 고갈, 서명 없는 웹훅으로 PG 조회 증폭, Secret·키 유출.

## 5. 우선순위

- 가능성·영향을 상·중·하로 쓰고 기존 통제를 반영해 critical·high·medium·low를 정한다. 순위를 바꾸는 가정을 함께 적는다.
- critical: 인증 없이 다른 사람의 PII·배송지 열람, 관리자 세션 획득, 결제 금액 변조 승인.
- high: 비회원 token 대량 유출 경로, fail-closed 우회로 인증 코드 발송 남용, `ENCRYPT_KEY`·`HMAC_KEY`·서명 키 노출.
- medium: 특정 사용자 lockout, 웹훅 남용으로 PG 조회 증폭, 일부 PII의 로그·외부 모니터링 노출.
- low: 존재 여부 수준 정보 노출, 쉽게 완화되는 소음성 DoS.

## 6. 가정 확인

- 최종 보고 전에 핵심 가정 3~6개와 질문 1~3개를 제시하고 답을 기다린다. 예: 운영 개시 여부, Sentry DSN 사용 여부, Ingress 앞 추가 프록시, 관리자 수·접속 위치.
- 답이 없으면 남은 가정과 순위 영향을 적고 권고를 조건부로 표시한다.

## 7. 완화책과 결과

- 기존 통제(근거)와 권고를 분리한다. 권고는 위치와 통제 종류를 쓴다. 예: "`RateLimitFilter`에 `<경로>` 전용 fail-closed 규칙 추가", "`<유스케이스>` 조회 조건에 `userId` 추가".
- 결과 순서: 요약 → 범위·가정·미해결 질문 → 구성과 경계(Mermaid 1개, 선택) → 자산 표(자산·이유·C/I/A) → 공격자 능력·비능력 → 진입점 표 → 악용 경로 → 위협 표(`TM-001`·우선순위·근거·권고) → 집중 검토 경로.
- 마무리 전 확인: 범위 안 진입점과 경계가 모두 위협 표에 반영됐는지, runtime과 CI·테스트를 섞지 않았는지, 가정과 사용자 답변이 반영됐는지.
- 결과는 응답으로 제공한다. 보관을 원하면 결정이 필요한 위험은 `docs/Idea/<번호>_<주제>/idea.md`, 채택한 통제는 해당 ADR 갱신으로 남긴다.
